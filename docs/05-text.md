# 05. メッセージ形式（暫定）

ゲームテキストは、docs/04 の数値テーブルとは別レイアウトの
「メッセージテーブル」としてアーカイブ内に入っている。
LZ10 セクションを展開すると、1 ブロックに**複数のメッセージテーブルが連結**されている。

確認できたテーブル名:

```
MessageCommon      共通メッセージ
MessageMapName     マップ名
MessageMapStage    ステージ名（stage_name グループ）
MessageNpcName     NPC名
MessageTalkTower   タワーの会話
d01_msg w01_msg …  マップごとの会話（マップIDの接頭辞）
```

名前の後ろに `message` / `voice` / `stage_name` といったグループ名が続く。

## エントリのヘッダ（確度: 低）

`5EFE0000` セクション36 の先頭:

```
0x0000  27 00 00 00    エントリ数 0x27 = 39
0x0004  0c 00 00 00
0x0008  40 00 00 00    レコード領域の開始
0x000C  23 28 00 00
0x0010  70 28 00 00  d4 01 00 00     (offset, size)
0x0018  50 2a 00 00  9c 00 00 00     (offset, size)
0x0020  f0 2a 00 00  10 00 00 00     (offset, size)
0x0028  00 2b 00 00  50 00 00 00     (offset, size)
0x0034  1a 28 00 00
0x0038  22 28 00 00
0x0040  01 00 37 00 03 00 03 00 07 00 "MessageCommon\0"
0x0058  02 00 e7 01 00 80 03 00 04 00 "message\0"
0x0070  （以降 UTF-16LE のテキスト本体）
```

レコードは `u16 × 5` の後ろに NUL 終端 ASCII 名が続く形に見えるが、
フィールドの意味は未確定。数値テーブルのヘッダモデルをそのまま当てると
名前フィールドが壊れるのはこれが原因。

## テキスト本体とルビ制御（確度: 高）

本文は **UTF-16LE**。制御は `U+0001` をエスケープとして、直後の1コードユニットが
オペコードになる。確認できた並び:

| 並び | 意味 |
|---|---|
| `U+0001 U+0038`（`'8'`） | ルビ対象（漢字）の開始 |
| `U+0001 U+0039`（`'9'`） | 読み（かな）の開始 |
| `U+0001 U+003A`（`':'`） | ルビ終了 |
| `U+0001 U+0037`（`'7'`） | 行／ブロック区切り |
| `$page$` | ページ送り |

実例（`U+0001` を `\x01` と書くと）:

```
\x01 8 電波人間 \x01 9 でんぱにんげん \x01 : だ、めずらしい！
```

→ 表示は「電波人間（ルビ: でんぱにんげん）だ、めずらしい！」

全文が漢字＋読みの対で入っているため、**漢字表記とかな表記の両方が
データとして取り出せる**。小学生向けのルビ表示切り替えのためと思われる。

`U+FF01 U+FF01`（`！！`）のような全角記号はそのまま入る。
