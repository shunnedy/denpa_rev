# 20. Ｗｉ-Ｆｉコロシアムの対戦相手データ

docs/13・14 の続き。対戦相手のパーティblob（1256バイト）の中身をコードから
完全に解明し、任意の電波人間を対戦相手として配れるようにした
（[`tools/colosseum.py`](../tools/colosseum.py)）。

## FREE! のＷｉ-Ｆｉコロシアムは「ダウンロード型」

バイナリに **HTTP POST が一切ない**（`POST` / `AddPostData` / `Content-Length`
送信コードがゼロ）。つまりゲームは**自分のパーティをアップロードしない**。
Ｗｉ-Ｆｉコロシアムは

1. `gameserver?req=rand3` で対戦相手を**ダウンロード**し、
2. ローカルでその相手と戦う

という作り。だから対戦相手を用意する ＝ `rand3` が返す blob を正しく作ること。

## `rand3` 応答のパース（`FUN_003e73xx`）

```
SUCCESS,<base64 A1>,<base64 B1>,<base64 A2>,<base64 B2>,...
```

1相手につき2フィールド。デコードして **1288バイト（0x142 u32）のエントリ**に詰める:

```
entry + 0x08   A: 32バイト  相手チーム名（UTF-16LE）
entry + 0x28   B: 1256バイト パーティblob
```

1回で最大5相手。戦闘は3相手を使い、足りないぶんは
**`FUN_001e8a04` がその場でランダム生成**する（＝この関数が blob の生成器＝
フォーマットの手本になる）。

## パーティblob（1256バイト = 0x4E8）

`FUN_0028e680`（初期化）＋ `FUN_00295aa4`（1体を詰める）が書き、
`FUN_00186140` が読み戻す。両者は完全な逆写像:

```
0x000  u32   有効な電波人間の数（生成器は 3 を書く）
0x004  u32   0
0x018  148バイト × 8   電波人間スロット（下記）
0x4BC  20B   代表の名前ブロック（名前テーブルのレコードから。表示用）
0x4D0  u32   チームID（乱数）
0x4D4  20B   0
```

### 1体 = 148バイト（0x94）スロット

252バイトのセーブレコード（docs/19）を詰め直したもの。
**HP・AP・EXP・各種タイムスタンプは入っていない** —— 戦闘側がレベルと
アンテナと外見からステータスを再計算する（docs/19 の式）ので、相手は
「遺伝子＋レベル＋ボーナス＋装備」だけで完全に表現できる。

| スロット | レコード | 内容 |
|---|---|---|
| `0x00` 4B | `+0x04` | （=1） |
| `0x04` 4B | `+0x08` | 作成タイムスタンプ |
| `0x08` 24B | `+0x14` | 名前＋読み |
| `0x20` 20B | `+0x4C` | 所有者名 |
| `0x34` 22B | `+0x60` | **外見遺伝子**（顔・体型・体色…） |
| `0x4A` 1B | `+0x76` | 性別・名前グループ |
| `0x4B` 1B | `+0x77` | 声タイプ |
| `0x4C` 1B | `+0x82` | 世代 |
| `0x4D` 1B | `+0x84` | 子作り・こどもフラグ |
| `0x4E` 1B | `+0x94` | アンテナ群 |
| `0x4F` 1B | `+0x95` | アンテナ段階 |
| `0x50` 2B | `+0x96` | レベル |
| `0x52` 2B | `+0x9C` | 変身先 |
| `0x54` 1B | `+0x9E` | 成長タイプ（下位ニブル） |
| `0x55` 1B | `+0x83` | 何代まで |
| `0x56` 6B | `+0xA0` | 今世代ボーナス |
| `0x5C` 6B | `+0xA6` | 永続ボーナス |
| `0x64` 32B | `+0xAC` | 装備8枠 |
| `0x84` 16B | `+0xEC` | 末尾 |

読み込み後、ローダ（`FUN_0023c8a8`）が種別ニブル（`+0x06`）を 6
（外部データ）に上書きする。

## ツール

```bash
# セーブの手持ちを対戦相手パーティにする
python3 tools/colosseum.py from-save savedata.bin --slots p0,p1,p2 -o team.blob
# 任意の252バイトレコードを詰める
python3 tools/colosseum.py pack a.denpa.bin b.denpa.bin -o team.blob
# pack/unpack が全フィールド往復することを検証
python3 tools/colosseum.py selftest savedata.bin
```

サーバは blob をそのまま `rand3` で配る:

```bash
python3 tools/denpa_server.py --port 8082 \
    --opponent "カゲトラ軍団:team1.blob" \
    --opponent-save "だれかのチーム:friend_save.bin" \
    --log access.log
```

`--opponent-save` は他人のセーブの手持ちをそのまま対戦相手にできる
（アップロードが無いゲームで「フレンドのチームと戦う」を擬似的に実現する）。

## 検証状況

- blob の pack/unpack はコードの逆写像で、実セーブ4体で全フィールド往復を確認
- ステータス再計算式は docs/19 で実機表示と一致
- **実機/Azaharでの対戦の成立は未確認**（このマシンから接続できないため）。
  接続時の全リクエストは `--log` に残るので、`req=rand3` が来て相手が
  表示・戦闘できるかを見て詰める

## まだ不明

- `0x4BC` の代表名ブロックの正確な用途（表示名か先頭個体か）。いまは先頭個体の
  名前をコピーしている
- `rand3` 以外（`rank` / `top10` / `total` / `player_data`）の各フィールドの意味。
  ランキング表示用で、対戦成立には不要と見られる
- `auth_token` が空でも実機で通るか（コード上は中断せず送信する）
