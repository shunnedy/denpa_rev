# 19. 電波人間レコードの完全解析（外見遺伝子・ステータス計算・持ち物）

セーブ内の電波人間1体＝**252バイト（0xFC）**のレコード。docs/16 で場所と
基本項目（HP/AP/レベル/EXP）を特定したあと、残り全部を `code.bin` のデコンパイル
（Ghidra、base v1.0.0。アドレスはすべて base 基準）で確定させた。
ここに書いた式は実セーブの4体（Lv5 と Lv50×3）のステータス画面と**一致を確認済み**。

ツール: [`tools/denpaedit.py`](../tools/denpaedit.py)（エディタ）、
[`tools/denpadict.py`](../tools/denpadict.py)（ROMから辞書 `data/denpa-dict.json` を生成）、
[`tools/test_denpaedit.py`](../tools/test_denpaedit.py)（自己テスト79項目）。

## セーブ内の配置（v1.17.0）

セーブ先頭 `0x14` から `(オフセット, サイズ)` の組が並ぶセクション表:

| # | オフセット | サイズ | 中身 |
|---|---|---|---|
| 5 | `0x2588` | `0xFC0` = 16 × 0xFC | **手持ち**（コードが使うのは8枠、領域は16枠） |
| 6 | `0x3548` | `0x40998` = 1050 × 0xFC | **ボックス** |
| 7 | `0x43EE0` | `0x7E0` = 8 × 0xFC | 予備（空） |

空き枠は先頭 u32（個体番号）が 0。

## レコード 0xFC バイト

```
+0x00 u32  個体番号（作成順の連番。0 = 空き）
+0x04 u16  1 << n（n = FUN_0027fa04() の値。通常 1）
+0x06 u16  bit4-7 = 種別(kind)  bit0-3 = 4  bit8 = ROM定義フラグ  bit9 = 所有者フラグ
+0x08 u32  作成日時（FUN_002e2124 で詰めた値）
+0x0c u8   地域コード（FUN_0027f948、日本=1）
+0x10 u32  名前番号（MessageDenpaName のインデックス。ゲット時/誕生時に抽選）
+0x14 24B  名前: UTF-16LE + NUL、続けて音声合成用の読み（半角カナの1バイトコード、docs参照）
           ＝名前プールの24バイトをそのままコピーしたもの
+0x2c..0x4b 0（作成時にクリア）
+0x4c 20B  所有者名 UTF-16LE（NNID/本体のニックネーム。Azaharなら "AZAHAR"）
+0x60 u16  種別ごとの識別子（下記）
+0x62 u16  現在のアンテナとくぎ（SkillData ID、レベルから再計算される）
+0x64 u8   頭（HeadData 0..70）
+0x65 u8   はだの質感テクスチャ (0..15)   +0x66 u8 かみがた (0..50)
+0x67 u8   まゆ (0..31)  +0x68 目 (0..63)  +0x69 鼻 (0..63)  +0x6a 口 (0..63)  +0x6b ほほ (0..31)
+0x6c u8   0
+0x6d u8   体型（BodyData 0..29）
+0x6e,0x6f 0
+0x70 u8   まだら模様の番号（0 = 単色）
+0x71 u8   体色A（ColorData 0..38）   +0x72 u8 体色B（0 = なし）
+0x73 u8   はだの色 (0..5)   +0x74 u8 かみの色 (0..11)
+0x75 u8   bit0: 単色上書きフラグ（色 = +0x75 >> 1）
+0x76 u8   bit0-3 = 性別/名前グループ(0..2)  bit4-5 = 第2グループ(0..2)  → 名前候補リストの選択に使う
+0x77 u8   声タイプ（名前の読みから算出。初期メンバーは 50 固定）
+0x78 u16  現在HP   +0x7a u8 現在AP   +0x7c,0x7d 状態（モンスター用）
+0x80 u16  幸福度（上限は世代表 ParameterCap の happy_max: 20/30/50/75/100/150/200/300/500）
+0x82 u8   世代 - 1（0 = 1代目）   +0x83 u8 何代まで - 1（6 = 7代まで）
+0x84 u8   bit0-1 = 子作り残り回数  bit2-7 = こども残り日数（0以外ならこうげき/ぼうぎょ半減）
+0x85 u8   転生回数（上限 250）
+0x86 u8   父のアンテナ群   +0x87 u8 母のアンテナ群（子作りで生まれた個体のみ）
+0x88 u32  更新日時
+0x8c u16 ×3  日付カウンタ（誕生日など、起点からの日数）
+0x94 u8   アンテナ群（AntennaGroup 0..120）  +0x95 u8 アンテナ段階（0..6、再計算される）
+0x96 u16  レベル   +0x98 u32 累積EXP（LevelData[レベル-1] 以上）
+0x9c u16  変身先モンスター（通常 0）
+0x9e u8   bit0-3 = 成長タイプ(0..2、アンテナ群から決まる)
+0x9f u8   世代表の +0x16（3/5/7/9/12/…）
+0xa0 6B   今世代のステータスボーナス（HP AP こうげき ぼうぎょ すばやさ かいひ）
+0xa6 6B   永続ステータスボーナス（転生・子作りで +0xa0 を割って加算）
+0xac u32 ×8  装備（0x80000000 | アイテムID、0 = なし。枠1 = うでわ系を確認）
+0xcc..0xeb 0
+0xec 16B  0（外部データからの取り込み時のみ使用）
```

### 種別（+0x06 bit4-7）と +0x60

| kind | 意味 | +0x60 |
|---|---|---|
| 3 | ROM定義のレア電波人間 | 定義テーブルの番号 |
| 4 | モンスター（戦闘中の敵） | モンスター番号 |
| 6 | 外部データから復元（すれちがい等） | 外見ハッシュ |
| 8 | 初期メンバー（かげとら等） | **外見ハッシュ** |
| 9 | NPC（コロシアム等） | ColosseumDenpa 番号 |
| 0xa | 子（通常） | 0 |
| 0xb | ゲットした個体 | ゲット元の番号（bit15 = 種類） |
| 0xc | 子（親のどちらかが 0xb/0xc） | 0 |

**外見ハッシュ**（FUN_0027f2f0）: 外見12バイト
`[+0x6d, +0x64, +0x65, +0x66, +0x67, +0x68, +0x69, +0x6a, +0x6b, +0x70, +0x73, +0x74]`
の **SHA-256** を取り、先頭4ワード（LE）の和を 32bit で折り返して
`(s mod 0xFFFF) + (s >> 16)` の下位16bit、0なら1。同じ外見の個体が既にいるかの判定に使う。
かげとらの保存値 `0x98A0` と一致。

## 体色と属性耐性

`ColorData`（39色、名前・RGB・ビットマスク）: 0 なし / 1 脱色 / 2 レア(0x1000) /
3-5 くろ / 6-8 あか / 9-11 みずいろ / 12-14 みどり / 15-17 だいだい / 18-20 きいろ /
21-23 あお / 24-26 しろ / 27-29 むらさき / 30-32 ももいろ / 33-35 きん / 36-38 ぎん
（各3段: 標準・こい・うす。同じマスク）。

色AとBのマスクの OR（A・Bが同系統の別の濃さなら `| 0x2000`）で `BodyColorData`（102行）を引く
（FUN_00246648 / FUN_0040a898）。1行 = 8属性 × 4bit 符号付きの耐性、ぼうぎょ%、追加効果。

| 色 | 耐性 |
|---|---|
| あか | 属性0 +2 / 属性5 -2 |
| みずいろ | 属性1 +2 / 属性0 -2 |
| みどり | 属性2 +2 / 属性1 -2 |
| だいだい | 属性3 +2 / 属性2 -2 |
| きいろ | 属性4 +2 / 属性3 -2 |
| あお | 属性5 +2 / 属性4 -2 |
| **しろ** | **属性6(光) +2 / 属性7(闇) -2**（かげとらの表示「光+2 闇-2」と一致） |
| むらさき | 闇 +2 / 光 -2 |
| ももいろ | 全属性 -1、追加効果 c=5 |
| きん | 属性0/7 -2、効果d 120% |
| ぎん | 属性4/5 -2、ぼうぎょ 150% |
| くろ+しろ（まだら） | 光 +1 / 闇 -1（ゆうきの表示「光+1」と一致） |

属性の番号: 6=光, 7=闇 は確定。0-5 は色の対応から 火・水・風・土・電気・氷 と推定
（3=だいだい, 4=きいろ の割り当てだけ入れ替わっている可能性がある）。

子の体色は `BodyColorGenetic`（78行 = 親の色の組み合わせ）の抽選表で決まる
（FUN_003c7998）。各行に「色A / 色B / 混色」の3候補と%が2セット。

## ステータスの計算式（FUN_0028fd88、4体で一致を確認）

保存されているのは現在HP/APだけで、最大HP・AP・こうげき・ぼうぎょ・すばやさ・かいひは
毎回計算される。

```
base[k]  = LevelStatusData[成長タイプ][レベル] を行間で線形補間（HP AP こうげき ぼうぎょ すばやさ）
s[k]     = base[k] × (AntennaGroup.mult[k]×2 + 748) / 1000      ← アンテナ群 +0x3d..+0x41
s[k]     = s[k] × (ParameterCap[世代].pct[k] + 1000) / 1000     ← 世代表 +0x19..+0x1d
HP       = s[0] × BodyData.hp% / 100
AP       = s[1] + HeadData.ap_bonus (+0x0c)                     ← 体型補正なし
こうげき = s[2] × BodyData.atk% / 100
ぼうぎょ = s[3] × BodyData.def% / 100 × BodyColorData.def% / 100
すばやさ = s[4] × BodyData.spd% / 100
各値 += 永続ボーナス(+0xa6) + 世代表の固定ボーナス + アンテナ群の固定ボーナス(+0 の6bit×5) + 今世代ボーナス(+0xa0)
かいひ   = BodyData.eva + 永続 + 今世代
こども中（+0x84 bit2-7 ≠ 0）: こうげき・ぼうぎょ = (x+1)/2
装備効果（種別 0x17: 能力値、0x10: 属性耐性、0x11: 属性）を加算
HP..すばやさ は 1..9999、かいひ は 0..50 に丸め。AP は群の mult[1] が 0 なら 0
```

整数除算はすべて切り捨て（ARM の magic-number 除算 `K1=0x10624DD3`=÷1000、`K2=0x51EB851F`=÷100）。

LevelStatusData は 3タイプ × 25行（Lv1,5,15,20,30,40,50,75,100,…,500）。
タイプ1は AP の伸びが低い。成長タイプはアンテナ群の `+0x1e` bit8-11 から決まる。

### 世代表 `ParameterCap`（10行）

| 世代 | レベル上限 | 幸福上限 | 能力% (HP AP 攻 防 速) | +0x16 |
|---|---|---|---|---|
| 1 | 15 | 20 | 0 0 0 0 0 | 3 |
| 2 | 30 | 30 | 10 4 10 10 10 | 5 |
| 3 | 50 | 50 | 20 7 20 20 20 | 7 |
| 4 | 70 | 75 | 30 12 40 40 30 | 9 |
| 5 | 100 | 100 | 50 15 60 60 40 | 12 |
| 6 | 150 | 150 | 70 20 100 100 50 | 15 |
| 7 | 250 | 200 | 90 24 140 140 60 | 18 |
| 8 | 350 | 300 | 110 28 180 180 70 | 21 |
| 9 | 1000 | 500 | 120 32 220 220 80 | 24 |

レベル上限に達するとEXPは溜まるがレベルは上がらない（Lv50の3体のEXPが Lv51 の必要値を超えているのはこのため）。
`LevelData[i]` = Lv(i+1) に必要な累積EXP（0, 10, 30, 71, 156, 275, …）。

### 転生（FUN_00239d10）と子作り（FUN_0023b594）

- 転生の条件（FUN_002a3b18）: 子作り残り回数 > 0、通常種別、世代 < 10、レベル ≥ 上限、次の世代表が有効
- 転生: 世代+1、転生回数+1、幸福0、+0x9f 更新、今世代ボーナス ÷ 世代表の係数 → 永続ボーナスへ
- 子作り: 顔パーツ7種（+0x65/66, 67, 68, 69, 6a, 6b, 73, 74）はそれぞれ親のどちらかをコイントス。
  両親で異なるパーツがあれば1つは確率で「逆の親」に差し替え（突然変異枠）。
  頭は HeadData の相性表（+0x0f〜、'F'=70 は無条件）と inherit% で決定。
  体型は親2体の体型番号（5の倍数で系統、余りで大きさ）を別々に抽選して合成。
  アンテナ群は両親の群の「組み合わせ表」（AntennaGroup +0x31〜、6組）に該当があれば%で合成群、
  なければ両親のどちらか（+0x1e の重みで抽選）。
  名前は `+0x76` の2つのグループから 3×3 の候補リスト表（値 2..10）を引いて、
  手持ち・ボックスにいない名前から抽選。世代 = 親の世代+1、何代まで = どちらかの親から継承。

## アンテナ

`+0x94` が群（121群）、`+0x95` が段階、`+0x62` が現在のとくぎID。段階はレベルが群の
しきい値（`+0x22` の u16×6、1000 = 無し）をいくつ超えたかで、とくぎは `tiers[段階-1]`、
段階0なら「アンテナのねっこ」(ID 1)。レベルや群を変えると `FUN_0028f564` が再計算するので
エディタも同じ規則で書き直す。

例: かぐら Lv50「すこしわざアップ」(群107、しきい値 51/151/251/401) → 段階0、とくぎ=ねっこ。
かげとら Lv5「ちょっとふっかつ」(群9、しきい値 1/31/71) → 段階1、とくぎ ID 29。

## 名前と音声

`MessageDenpaName`（2,765件）は1件につき **名前（UTF-16）と読み（半角カナ1バイトコード）**の
2本の文字列を持つ。レコードには名前プールの位置から24バイトがそのままコピーされるので、
`+0x14` に名前、その NUL の直後にプール上で隣接していた読みが入る（隣接していない個体では空）。
読みのコードは JIS X 0201 の半角カナ（ｱ=0xB1 … ﾝ=0xDD）に、濁点 0xDE・半濁点 0xDF を後置、
`0x27` はアクセント記号。`denpadict.py` が名前表の2,765組から**かな→コード表**を学習して辞書に入れ、
エディタは名前を書き換えるとき読みも生成する（かげとらの保存値と一致することを確認）。

## 持ち物（インベントリ）

`ScriptFlag::GetItemNum` → `FUN_002e0470`: 所持数は docs/16 の**ビット詰め変数ストア**にある。

| 変数 | 幅 | 要素数 | 意味 |
|---|---|---|---|
| `0x1d` | 7bit | 3000 | アイテムごとの所持数（添字 = ItemData のインデックス = アイテムID） |
| `0x1e` | 7bit | 3000 | 第2の個数配列（預かり分。通常 0） |

v1.17.0 セーブでは変数ストアが `0x965FF` から始まり、var 0x1d は bit 65918 から
（`data/variables.json`）。上限は1種99（アイテム定義の +0x49 が 0 のとき。それ以外は定義値）。
装備中のアイテムも所持数に含まれる（かげとらの「ちからのうでわ」が x1 として存在）。

## エディタ

```
python3 tools/denpaedit.py save.bin list                  # 手持ち・ボックス一覧
python3 tools/denpaedit.py save.bin show p0 b1            # 全項目＋計算ステータス＋属性耐性
python3 tools/denpaedit.py save.bin set p1 level=50 antenna=すこしわざアップ --out new.bin
python3 tools/denpaedit.py save.bin set p0 colora=むらさき colorb=きん mix=3 head=12 eye=40 --out new.bin
python3 tools/denpaedit.py save.bin set p0 name=たろう gen=5 maxgen=7 --out new.bin
python3 tools/denpaedit.py save.bin new b5 name=てすと level=15 antenna=ちょっとふっかつ colora=あか --out new.bin
python3 tools/denpaedit.py save.bin new b6 --from p1 name=コピー --out new.bin
python3 tools/denpaedit.py save.bin copy b0 p2 / move / swap / delete / export / import
python3 tools/denpaedit.py save.bin items
python3 tools/denpaedit.py save.bin item キズぐすり 99 --out new.bin
python3 tools/denpaedit.py save.bin fields
```

- レベル・アンテナ群を変えると段階・とくぎ・成長タイプ・外見ハッシュを自動で整合させる
- `new` は作成後に計算した最大HP/APを現在値に入れる
- 計算ステータスは装備効果を含まない（装備効果テーブルの実行時構造は未解析。
  かげとらの「ちからのうでわ」= こうげき+4 のぶんだけ表示と差が出る）
- 自己テスト: `DENPA_SAVE=savedata.bin python3 tools/test_denpaedit.py`
