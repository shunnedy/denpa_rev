# 15. キャラクター・チームのデータ構造

Ｗｉ-Ｆｉコロシアムの対戦相手blob（1256バイト、docs/13）の中身を詰めるため、
ROM内にある同種の構造——オフラインのコロシアム用NPCチーム——を解析した。

## `ColosseumDenpaTeam`（124バイト = 1チーム）

`colosseumDenpaTeam_rank<1-5>_<02..12>.bin` が30本、各3レコード。
ランク5の例（`rank5_12`）:

```
+  0  u32  0x80000001                      種別
+  4  u32  プール内オフセット                チーム名
+  8  u32 × 8  0x80000101 … 0x80000108     **メンバー8体のID参照**
+ 40  u32  0x80000002                      ?
+ 44  u16  10 (+ 0xD0D0 フィラー)
+ 48  (u32 ID, u16 個数, 0xD0D0) × 7       **持ち物**（例: ID 0x31×5, 0x0c×5, 0x2c×3）
+120  u16 1, u16 400
```

チーム名はプールにUTF-16LEで入っている:

```
マスタースピリッツ / グレートジャイアンツ / ブラックタイガース
```

**1チーム = 名前 + メンバー8体 + 持ち物7枠**。

## `ColosseumDenpa`（120バイト = 1体）

`colosseumDenpa.bin`、585レコード。

```
+  0  u32 × 3   プール内オフセット（名前など）
+ 12  4バイト    パック値
+ 16  u32 × 8   小さい値（下記）
+ 48  u32 × 6   **装備6枠のアイテムID参照**
+ 72  u32 × 2   常に空
+ 80  u32  0x80000003
+ 84  u16, u16
+ 88  8バイト
+ 96  u8 100, u8, 70 70 70 70
+104  ステータス的なバイト列
+112  100 100 100 100 100 100, 00 00     **6つの100**
```

### `+48` の6枠が装備であることの根拠

| | 非ゼロ | 値域 | 種類 |
|---|---|---|---|
| slot0 | 548/585 | 1547〜3211 | 82 |
| slot1 | 574/585 | 1607〜3302 | 102 |
| slot2 | 567/585 | 1848〜3516 | 109 |
| slot3 | 551/585 | 1933〜3612 | 78 |
| slot4 | 583/585 | 1724〜3418 | 122 |
| slot5 | 567/585 | 2007〜3686 | 132 |

6枠ともほぼ常に埋まっており、値域が**枠ごとに別の帯**にずれている。
装備テーブルがちょうど6種あり（`equipInfo_face` 256 / `cloth` 365 /
`hand` 294 / `foot` 206 / `neck` 265 / `back` 347、いずれもレコード長60B）、
アイテムID空間（`ItemDataCore` 3232 / `ItemData` 3854）の
それぞれ別の帯を占めていることと整合する。

### `+16` の8枠

| | 非ゼロ | 値域 | 種類 |
|---|---|---|---|
| slot0 | 66/585 | 2〜1110 | 53 |
| slot1 | 352/585 | 1〜9 | 9 |
| slot2 | **585/585** | 3〜38 | 35 |
| slot3〜7 | 78〜124/585 | 3〜38 | 19〜26 |

slot2 だけ全レコードで埋まっている。値域1〜38は `SkillData`（405）の
IDには収まらないので、とくぎのIDではない。アンテナ種別・性格・
成長タイプといった小さな列挙値と見られるが**未確定**。

### 末尾の6つの100

`+112` に `64 64 64 64 64 64` が並ぶ。電波人間のステータスは
HP / AP / こうげき / ぼうぎょ / すばやさ / かいひ の**6項目**なので、
NPCのステータス補正が全項目100%、という読みが自然
（RPG3の解析でも同じ6項目構成だった）。`+96` の `46 46 46 46` = 70×4 も
同種の係数と思われる。

## 対戦相手blobとの関係（推定）

Ｗｉ-Ｆｉコロシアムの相手データは**1256バイト**（docs/13）。

```
1256 = 16 + 10 × 124
1256 =  8 + 10 × 124 + 8
```

チームレコードが124バイトである以上、**124バイト単位で10枠**という
読みが素直。ただしオンラインの相手はプレイヤーが育てた電波人間なので、
ROMのIDを指すだけでは足りず、1体ぶんのデータを丸ごと持つ必要がある。
124バイトに1体を詰めるなら `ColosseumDenpa`（120B）＋αとほぼ同じ密度に
なるので、**同系のレコードを10体分並べた形**と考えられる。

**これは推定であって未確定。** 確定には実際にアップロードされた
blobのサンプル（＝実機かエミュで `req=current_party` を観測する）か、
blobを読む側のコードを追う必要がある。

## MODとしての意味

- `ColosseumDenpaTeam` は**名前・メンバー8体・持ち物**がすべて
  ROM内のテーブルなので、`tdmpack.py` で書き換えれば
  **オフラインのコロシアムの対戦相手を自由に差し替えられる**
  （レコード長124Bを保つ限り安全）
- `ColosseumDenpa` の装備6枠を書き換えれば、NPCの装備を変えられる
- 自作の対戦相手をサーバから配るには、1256バイトblobの正確な
  レイアウトが必要。そこが最後の壁
